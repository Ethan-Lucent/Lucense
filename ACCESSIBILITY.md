
# Accessibility

## Our Commitment

Lucense aims to provide an accessible and comfortable experience for everyone, regardless of ability or preferred method of interaction.

Accessibility is an ongoing development priority across Windows, Linux, and Android.

## Accessibility Principles

We aim to provide:

- Readable typography and sufficient color contrast.
- Clear visual hierarchy and consistent navigation.
- Descriptive labels for interactive elements.
- Keyboard navigation wherever practical.
- Screen reader compatibility where supported.
- Visible keyboard focus indicators.
- Scalable layouts and adaptable UI components.
- Meaningful error messages and interaction feedback.
- Alternatives to information conveyed exclusively through color.

## Visual Accessibility

The interface should prioritize readability, consistency, and clarity.

Contributors should consider:

- Text and background contrast.
- Font scaling and readability.
- Distinguishable interactive states.
- Consistent icons and visual indicators.
- Avoiding unnecessary visual clutter.

## Keyboard and Navigation

Desktop interfaces should support keyboard navigation wherever practical.

Interactive components should provide:

- Logical focus order.
- Visible focus indicators.
- Predictable keyboard behavior.
- Accessible interaction alternatives.

## Screen Readers and Assistive Technologies

Where supported by the platform, UI components should expose meaningful accessibility information.

This includes:

- Descriptive content labels.
- Appropriate semantic roles.
- Meaningful descriptions for images and icons.
- Logical navigation order.
- Announcements for important state changes.

## Motion and Animations

Lucense uses animations and visual effects.

We aim to accommodate users who:

- Prefer reduced motion.
- Experience motion sensitivity.
- Need less visually dynamic interfaces.

Animations should never interfere with essential functionality.

## Reporting Accessibility Issues

If you encounter an accessibility barrier, please report it through GitHub Issues:

https://github.com/Ethan-Lucent/Lucense/issues

Use the `accessibility` label when available.

Please include:

- Lucense version.
- Operating system and platform.
- Relevant assistive technology.
- Steps to reproduce the issue.
- Expected and actual behavior.
- Screenshots or recordings, if applicable.

## Contributing

Accessibility improvements are welcome.

Examples include:

- Improving color contrast.
- Adding missing accessibility descriptions.
- Improving keyboard navigation.
- Fixing focus management.
- Improving screen reader support.
- Supporting reduced-motion preferences.
- Improving text scaling and layout adaptability.

## Current Limitations

Accessibility support is continuously evolving.

Not every interface, platform, or assistive technology combination has been independently audited.

Lucense does not currently claim complete WCAG conformance.

## Our Approach

Accessibility is a shared responsibility.

We welcome feedback, testing, and contributions that make Lucense more usable for everyone.
